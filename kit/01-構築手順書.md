# FixMyStreet 日本語版 構築手順書（Docker／VPS編）

実測環境: Ubuntu 22.04、Docker 28.4、Docker Compose v2.39、公式イメージ `fixmystreet/fixmystreet:stable`（Debian 11ベース）。2026年9月7日に名古屋市の地図上で日本語の通報フォームが動くところまで確認。

## 1. 準備

```bash
git clone https://github.com/katsushi2441/fixmystreet-jp.git
cd fixmystreet-jp
docker compose version
free -h            # 2GB 以上を推奨
ss -ltn | grep -E ':8000 |:18382 '   # 使うポートが空いているか
```

公式の `docker-compose.yml` は nginx を **8000** 番で公開します。他のサービスが 8000 を使っていたら、同梱の `docker-compose.override.yml`（18382 番の例）のポートを書き換えてください。

## 2. 設定（conf/general.yml-jp）

`docker-compose.override.yml` は、公式の `conf/general.yml-docker` の代わりに `conf/general.yml-jp` をコンテナに渡します。次の項目を自分の値にします。

| 項目 | 値の例 | 意味 |
|---|---|---|
| `BASE_URL` | `https://tsuho.example.jp` | 公開URL。メール内リンクにも使われる |
| `EMAIL_DOMAIN` / `CONTACT_EMAIL` / `DO_NOT_REPLY_EMAIL` | 自分のドメイン・アドレス | 通知メールの差出人 |
| `LANGUAGES` | `- 'ja,Japanese,ja_JP'` を先頭に | 先頭が既定言語 |
| `MAPIT_URL` | `https://global.mapit.mysociety.org/` | 日本の行政境界（OpenStreetMap） |
| `MAPIT_TYPES` | `[ 'O07', 'O08' ]` | O07=市区町村、O08=政令市の区 |
| `SMTP_SMARTHOST` ほか | メールサーバー | 通報を担当部署へメール送信するときに必要 |

MapIt Global は API キー無しでも点→区域の問い合わせが通りました（2026-09-07 実測）。本番で大量に叩く場合は mySociety の利用条件を確認してください。

## 3. 起動と日本語化

```bash
docker compose up -d
docker compose ps           # 4つが Up（postgres は healthy）になるまで20〜30秒
# 日本語ロケールと翻訳の生成（初回のみ。イメージには日本語が入っていない）
docker compose exec fixmystreet bash -lc '
  grep -q "^ja_JP.UTF-8" /etc/locale.gen || echo "ja_JP.UTF-8 UTF-8" >> /etc/locale.gen
  locale-gen
  cd /var/www/fixmystreet/fixmystreet && commonlib/bin/gettext-makemo
  systemctl restart fixmystreet'
curl -s -H "Accept-Language: ja" http://127.0.0.1:18382/ | grep -c 通報   # 0 でなければ日本語化OK
```

管理者を作ります（管理画面 `/admin` 用）。

```bash
docker compose exec fixmystreet bash -lc 'cd /var/www/fixmystreet/fixmystreet && bin/createsuperuser admin@example.org <パスワード>'
```

## 4. 対応機関（body）と分類（category）

通報は「対応機関」に紐づく「分類」を選んで送られます。対応機関には MapIt の区域を割り当てます。

```bash
# 緯度経度から区域 id を引く（例: 名古屋市役所）
tools/find-area.sh 136.9066 35.1815
#   中区 871979 O08 / 名古屋市 989637 O07 / 愛知県 960693 O04
# DB に直接登録（tools/nagoya-body.sql の名前・id・分類・メールを自分のものに書き換えてから）
docker compose exec -T postgres psql -U fms -d fixmystreet < tools/nagoya-body.sql
docker compose exec fixmystreet systemctl restart fixmystreet
```

管理画面から登録する場合は `/admin/bodies`（対応機関の追加）→ `/admin/body/<id>`（分類とメールの追加）です。管理画面のログイン画面はパスワード欄が折りたたまれているので「サインイン」を押してから入力します。

## 5. 動作確認

ブラウザで `http://<ホスト>:18382/report/new?latitude=35.1815&longitude=136.9066` を開き、

- 名古屋市役所付近の地図が出る
- 「分類」に登録した3件（不法投棄・街路灯の故障・道路の穴・舗装の破損）が日本語で並ぶ
- 「次へ」で詳細入力に進める

ことを確認します。`/reports` で通報一覧、`/alert` で地域の通知登録が日本語で表示されます。

## 6. 公開

VPS の nginx や Caddy でリバースプロキシし、`BASE_URL` を公開URLに合わせて `docker compose restart`。HTTPS は Caddy が簡単です。

## 落とし穴（実測）

1. **`cgroup: host` と `/sys/fs/cgroup` のマウントを消すと起動しない**。コンテナ内で systemd が app サーバーを管理しているため
2. **日本語が出ない**＝`locale-gen` か `gettext-makemo` か再起動のどれかが抜けている。`locale -a | grep ja` と `locale/ja_JP.UTF-8/LC_MESSAGES/FixMyStreet.mo` の有無で切り分け
3. **ポート 8000 が他サービスと衝突**。override でポートを変える（本キットは 18382）
4. **`/my` や `/faq` が 404**。`/my` はログイン後のページ、`/faq` は既定 cobrand に無い。異常ではない
5. **通報フォームに分類が出ない**＝対応機関に区域（body_areas）が無いか、分類（contacts）の `state` が `confirmed` でない
6. **MapIt を `fakemapit`（公式 Docker の既定）のままにすると区域が引けない**。`MAPIT_URL` を Global に
7. **メールが飛ばない**＝`SMTP_SMARTHOST` 未設定。通報自体は DB に保存されるので、後から設定できる
8. **翻訳に約50件の英語が残る**（管理画面のヘルプ文）。運用に支障はないが、直したい場合は `.po` を編集して `gettext-makemo`
